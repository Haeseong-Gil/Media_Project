## 선택창 숨김과 게임 정지

- 생존자 사건이 발생하면 날짜·배급·운행·탐사·위험도 진행을 멈춘다.
- 오른쪽 위 **상태 보기 · 게임 정지**를 누르면 선택창을 숨겨 전체 자원과 상태를 읽을 수 있다.
- 숨긴 동안 버튼은 **수용·거절 창 다시 열기**로 바뀐다.
- 숨겨져 있어도 수용 판단은 대기 상태다. 시간과 자원은 움직이지 않으며 출발·파견·인원 변경도 막는다.
- 창을 다시 열어 **5명 수용** 또는 **거절**을 선택한 뒤에만 게임 진행을 재개한다.
- 수용 후 인원은 +5, 하루 필요 식량은 +15. 거절은 인원을 유지한다. 신뢰 수치는 없다.

## 구현 기본 처리

다음은 새 시스템을 추가하지 않고 공백을 처리한 구현 선택이며 피드백에 따라 변경할 수 있다.

- 시작 구역과 운행 상태는 기존 임시안인 일반 구역·정차 상태를 유지했다. 타이틀 시작 버튼을 누르면 게임 시간이 흐른다.
- 정차할 때 운행 5초 소비 주기의 경과를 보존하고 재출발하면 이어 센다. 출발 비용 3은 별도로 매 출발에 적용한다.
- 연료 3 미만이면 출발을 막는다. 정확히 3일 때는 비용을 내고 연료 0이 되어 즉시 정차한다.
- 같은 탐사 시점에는 자원 확보 → 위험 판정 → 손실 차감 → 강제 귀환 순으로 처리한다. 날짜 종료까지 겹치면 그 시점의 하루 배급도 처리한다.
- 내부 자원은 소수를 유지하며 화면은 소수점 첫째 자리로 표시한다. 반복 획득마다 정수 반올림을 하지 않는다.
- 위험 판정 확률의 최댓값은 100%다.
- 생존자 발견을 위해 최소 탐사 시간을 추가하지 않았다. 첫 폐역 파견 뒤 귀환이 사건 조건이다.
- 실패 UI의 **타이틀로 돌아가기**로 타이틀을 표시한다. 자동으로 새 RUN을 시작하지 않는다.

인원 변화·탐사 없이 시작값으로 기다리면 첫 배급 부족은 30분, 실패는 65분이다. 검증에서는 시간을 직접 진행시켜 실패를 확인했다. 실제 65분을 기다려 관찰한 것은 아니다. 발표 종료 방식이나 최종 엔딩은 추가하지 않았다.

## Unity 조작 순서

1. **Project** 창(파일 목록)에서 `Assets > Scenes > PrototypeMain`을 더블클릭한다.
2. 상단 **Tools > Yeolguk Train > FHD Preview**를 눌러 Game 창을 1920×1080으로 맞춘다.
3. 상단 **▶ Play**를 누르고 타이틀의 **시작**을 누른다.
4. **출발 (연료 3)**을 누른다. 약 60초 뒤 구역 문구가 폐역으로 바뀌면 **정차**한다.
5. `+`/`−`로 인원을 선택하고 **탐사 파견**을 누른다. 시작 6명에서는 3~5명 선택 가능하다.
6. **즉시 귀환**하거나 사고 후 2명으로 줄어 강제 귀환하면 첫 폐역 생존자 사건이 열린다.
7. **상태 보기 · 게임 정지** → **수용·거절 창 다시 열기**를 눌러 본다. 날짜의 초·식량·연료가 같은지 확인한다.
8. 수용 또는 거절하면 시간이 다시 흐른다. 다음 폐역 귀환에는 사건이 반복되지 않는다.

### 기다리지 않고 선택창만 확인하기

Play를 껐다 켜서 타이틀에 둔 다음, 시작 버튼 대신 상단 **Tools > Yeolguk Train > Preview Survivor Choice**를 누른다. Editor 도구가 운행 60초를 계산해 첫 폐역 귀환 상태를 만든다. 게임 설정값은 바꾸지 않는다. 이후 실제 마우스로 상태 보기·다시 열기·수용 또는 거절을 확인한다.

### 실패와 새 RUN만 확인하기

Play를 껐다 켜서 타이틀에 두고 **Tools > Yeolguk Train > Preview Failure Screen**을 누른다. Editor 도구가 실패 조건까지 시간을 계산한다. 실패 UI의 **타이틀로 돌아가기** → 타이틀 **시작**을 눌러 인원 6·식량 100·연료 1000으로 복원되는지 확인한다.

위 미리보기는 Editor 전용 개발 도구이며 게임 안의 시간 가속 기능이 아니다.

## 검증 결과

- 게임·Editor 코드와 씬 제작 도구 컴파일: 오류 0·경고 0.
- 실제 게임 규칙 클래스 검사 **25/25 통과**. 소비 주기·출발 비용·파견 제한·이산 획득·구역/인원 보너스·위험 증가·인원 구간별 손실·강제 귀환·사건 1회·결정 대기 정지·굶주림 0일차와 7일차 실패·큰 시간 간격에서의 동일 결과를 확인했다.
- 실제 Play 씬의 레이캐스트와 버튼 이벤트 검사 통과. 타이틀 → 파견·귀환 → 숨김/재표시 → 수용 → 사건 중복 방지 → 실패 → 타이틀 → 새 RUN 초기화를 확인했다.
- 창을 숨긴 상태에서 게임 진행 함수에 10,000초를 전달해도 시간·배급 경과·식량·연료가 같은지 확인했다.
- 작업 중 자동 UI 도구가 팝업 활성화와 같은 프레임에 검사해 assertion 오류가 두 차례 발생했다. 렌더링한 다음 프레임에 검사하도록 도구를 수정한 뒤 통과했다.
- 임시 한글 글꼴이 재구성될 때 글자 배치를 갱신하도록 보완했다. 타이틀·실패·선택창·숨긴 상태를 실제 FHD 캡처로 확인했다.
- 수정 후 새 Play 세션의 Console 실제 집계는 오류 0·경고 0. Pipeline의 이전 도구 오류 누적 기록과 구분한다.

사용자의 물리 마우스 확인과 Windows 실행 파일·발표 리허설은 자동 검사와 별도다. 실행 파일을 생성·실행했다고 기록하지 않는다.
