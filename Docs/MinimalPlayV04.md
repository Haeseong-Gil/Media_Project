## 명세에 없는 임시 처리 방식

수치가 없어 연결에 필요한 다음 사항은 임시로 정했고 최종 설계로 취급하지 않는다.

- 일반 구역에 정차한 상태로 시작한다. `RUN 시작`을 누르기 전에는 시간이 멈춘다. 누른 뒤에는 정차·파견 인원 선택·수용 판단 중에도 시간이 계속 흐른다. 게임의 일시정지 기능은 추가하지 않았다.
- 정차한 상태에서 파견한다. 파견대가 밖에 있으면 귀환 후 출발한다. 한 귀환의 생존자 판단을 마친 뒤 다음 팀을 파견한다.
- 매 하루가 끝날 때 현재 전체 인원분을 소비한다. 탐사 중인 인원도 식량을 소비한다. 식량이 전원분에 모자라면 남은 식량을 0으로 만들고 굶주림 +1일, 전원분을 충족하면 연속 굶주림을 0으로 되돌린다.
- 두 자원은 인원에 비례해 동시에 쌓인다. 비축량에는 귀환 시 한 번만 더한다. 이전 고정 시연의 식량 24·출발 에너지 10 같은 값은 사용하지 않는다.
- 손실은 무작위가 아니라 파견 경과 40초마다 1명 발생한다. 2명 중 1명이 손실되면 당시 운반 중이던 두 자원도 각각 절반으로 줄어든다. 이후에는 1명분만 수집한다. 전원 손실이면 운반량을 잃고 팀이 해제되며 생존자 요청은 열리지 않는다.
- 생존자 요청은 매 귀환에 3명으로 표시한다. 수용 즉시 식량을 빼지 않고 이후 하루 필요량이 늘어난다. 반복 귀환으로 생존자가 계속 발생하는 것은 임시 연결이며 밸런스 검증 완료를 뜻하지 않는다.
- 전체 인원이 0일 때의 별도 결말이나 자원 고갈 보완 규칙은 새로 만들지 않았다. 이 상태에서 파견 가능한 인원이 없다는 표시만 유지한다.

## Unity에서 실행하는 순서

1. **Project** 창에서 `Assets > Scenes > PrototypeMain`을 더블클릭한다. Project는 파일 목록, 씬은 게임 화면 배치를 저장한 파일이다.
2. 상단 **Tools > Yeolguk Train > FHD Preview**를 누른다. Game 창이 1920×1080 미리보기로 열린다.
3. 상단 **▶ Play**를 누른다. Game 창의 `RUN 시작`을 누르면 시간 진행이 시작된다.
4. `출발`을 누르고 구역 문구와 연료 감소를 본다. 약 12초에 폐역으로 바뀐다. `정차`를 누르면 연료 소비가 멈춘다. 연료가 먼저 0이 되면 자동 정차한다.
5. `+` 또는 `−`로 파견 인원을 고르고 `탐사 파견`을 누른다. 탐사 영역의 운반 식량·연료가 동시에 늘어난다. 최초 확인에는 2~3명, 5~10초 탐사를 권장한다.
6. `즉시 귀환`을 누르면 비축량에 들어온다. `생존자 수용` 또는 `거절`을 선택하고 인원과 하루 필요 식량을 본다. 연료를 보충했다면 다시 출발할 수 있다.
7. 파견 상태를 40초 이상 유지하면 임시 손실과 운반량 감소를 볼 수 있다. 한 명만 파견했으면 전원 손실이 된다.
8. 확인이 끝나면 상단 Play를 다시 눌러 종료한다. Editor에서 Play를 껐다 켜는 것은 개발 중 테스트 방법이며 게임 안의 재시작 기능은 아니다.

`Window > General > Console`은 오류·경고를 보여주는 창이다. 검증 도구의 PASS 로그는 일반 정보이며 오류가 아니다.

## 임시값을 바꾸는 순서

1. Play를 종료한다. 실행 중 변경은 종료할 때 사라질 수 있다.
2. **Hierarchy** 창(씬 안 오브젝트 목록)에서 `MinimalRunCanvas`를 선택한다.
3. **Inspector** 창(선택 대상의 설정)에서 `Minimal Run Screen > Tuning`을 펼친다.
4. 예를 들어 하루 길이를 바꾸려면 `Seconds Per Day`를 바꾼다. 손실을 잠시 끄려면 `Seconds Per Explorer Loss`를 `0`으로 바꾼다.
5. `Ctrl+S`로 씬을 저장하고 Play로 재확인한다. 화면 맨 아래의 임시값 안내도 현재 설정을 따른다.

테스트 메뉴 `Tools > Yeolguk Train > Verify Minimal Run`은 코드의 기본 임시값으로 계산 검증을 한다. 사용자가 Inspector에서 바꾼 게임 설정을 전부 검증하는 도구는 아니다. `Verify Live UI`는 기본 임시값의 RUN 시작 전 Play 상태에서 버튼 연결을 자동 검사한다. 보통은 위 수동 조작만으로 확인하면 된다.

## 검증 근거

Codex가 직접 수행했다.

- Editor와 게임 코드 컴파일: 오류 0, 경고 0.
- 규칙 검증 16/16 통과: 시작 전 정지, 자유 정차, 연료 고갈과 보충, 고정 구역, 두 자원 입고, 중복 방지, 수용·거절, 폐역 효율, 단일 팀, 7일 굶주림, 식사 후 굶주림 초기화, 손실과 수집량 감소, 전원 손실, 큰 시간 간격과 분할 시간의 일치, 150초 비강제 종료, 새 인스턴스 초기화.
- 실제 Play 씬에서 UI 레이캐스트(버튼 위치에 입력이 닿는지 검사)와 클릭 이벤트로 RUN 시작·인원 선택·파견·귀환·수용·거절·버튼 잠금 통과.
- 실제 FHD 캡처의 한글·상하 영역과 수치 변경 후 자원 표시 확인. 숫자 변경 뒤 Legacy Text 배치가 깨지는 현상을 발견해 전체 배치 무효화로 수정한 뒤 재확인했다. 관련 API: https://docs.unity.com/en-us/engine/6000.5/script-reference/unityengine/textgenerator/invalidate
- Play 재실행 시 초기 보고로 복원 확인. 위 영역 1920×720, 아래 영역 1920×360을 실제 씬에서 조회해 확인.
- 검사 시 Console 오류 0, 경고 0. 기존 테스트의 PASS 로그만 존재.

아직 확인하지 않은 부분은 사용자의 새 화면 실제 마우스 조작, 설명 포함 2~3분 리허설, Windows 실행 파일, 발표 장비 가독성이다. 자동 UI 이벤트 검사는 물리 마우스 조작 검증과 구분한다. 기존 Build 목록은 SampleScene이며 이번에 실행 파일을 만들었다고 기록하지 않는다.

## 변경 파일과 보존

| 경로 | 역할 |
|---|---|

Unity가 생성한 새 스크립트 `.meta`는 연결 식별자이므로 함께 보존한다. 이전 `PrototypeReportScreen.cs`와 첫 구현 기록도 보존했다. 편집 모드에서는 Windows 임시 한글 폰트를 아직 적용하지 않아 한글이 네모로 보일 수 있으며 Play 중 한글을 확인했다. 정식 글꼴·아트는 이번 범위에서 제작하지 않았다.

변경 전 씬 사본은 채팅 작업 폴더 `.work/before-v04/PrototypeMain.unity`에 있다. 실제 프로젝트 밖의 개발 사본이며 게임 진행 저장 기능이 아니다. 현재 변경은 로컬 미커밋 상태이고 원격 업로드를 수행하지 않았다.

사용자는 범위·임시값 허용 결정을 했으며, AI는 코드·씬 UI 작성과 위 검증을 도왔다. 다음에는 사용자의 플레이 피드백으로 임시값과 조작 규칙을 확정하거나 축소한다. 다른 절의 기획을 자동으로 구현 목록에 추가하지 않는다.
